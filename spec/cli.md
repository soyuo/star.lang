# Command-Line Interface

Status: draft

The `star` CLI provides source checking and building, single-program execution,
online-judge fixture execution, process-level timing, and source encoding and
formatting tools. It preserves guest standard input and output for `run`;
diagnostics are written to stderr.

## Commands

| Command | Contract |
|---|---|
| `star new <directory>` | Creates a project directory with `Star.toml`, `src/main.star`, and `.gitignore`. The package name is the final directory component. The destination must not already exist. |
| `star init [package-name]` | Initializes the current directory with the same files. If no package name is supplied, the directory name is used. Existing generated files are never overwritten. |
| `star check [file.star|file.starc] [options]` | Parses and semantically analyzes source, lowers and compiles the supported source subset, then verifies the generated bytecode. A `.starc` input is verified without execution. If omitted, it uses the nearest `Star.toml` entry. |
| `star build [file.star] [--output <file.starc>] [options]` | Compiles supported source to verified `.starc`. The default output replaces the source extension with `.starc`. If the source is omitted, the `entry` in the nearest `Star.toml` is used. The initial lowering supports literals, catalog instructions, function declarations, conditionals, loops, `FOR`, scopes, and control transfers. `TRY/CATCH/FINALLY` lowering is not yet supported and produces a source diagnostic. |
| `star run [file.star|file.starc] [options]` | Executes source with the reference interpreter or bytecode with the VM. If the file is omitted, the `entry` in the nearest `Star.toml` is used. Input and output bytes are preserved. Output is flushed on success and failure. |
| `star test --suite oj [--solutions <directory>]` | Runs the `tests/oj` paired source/bytecode harness. Solutions use `<case-id>.star` and `<case-id>.starc`; the default directory is `<repository>/tests/oj/solutions`. Requires Python 3.11 or newer. |
| `star bench [file.star|file.starc] --iterations <count> [--input <file>] [execution options]` | Starts a fresh `star run` process for every iteration, feeds the same bounded input bytes each time, discards guest stdout, and reports total and mean wall time. Process startup is included. Without `--input`, each run receives empty input. If omitted, it uses the nearest `Star.toml` entry. |
| `star fmt <file.star> [--write]` | Parses source and prints canonical four-space-indented source. `--write` replaces the input file. |
| `star minify <file.star> [--write]` | Validates source and removes formatting whitespace. `--write` replaces the input file. |
| `star encode (--int N | --float N | --string TEXT | --file PATH | --opcode NAME)` | Emits a valid Star source representation for the selected value or ordinary assigned opcode. |
| `star decode <source-file>` | Decodes one value or ordinary instruction token produced by `star encode`. |
| `star help` | Prints command usage and stable exit codes. |

`check`, `build`, and `run` accept `--strict` for source whitespace handling.
`check` and `build` accept `--max-memory`, `--max-stack`, and
`--max-instructions` as verification ceilings. `run` and `bench` accept those
ceilings plus `--max-call-depth` and `--timeout`; `run` also accepts `--stats`.
`build` and `check` use file paths when supplied, otherwise they read the nearest
`Star.toml` entry. The initial manifest schema is `schema_version = 1`, followed
by `[package]` with `name`, `version`, and relative `entry`. Project creation
does not overwrite existing files. `build` and `check` do not execute the
program, so timeout, call depth, and runtime
statistics do not apply. Resource defaults and accounting are defined in
`spec/resource-limits.md`.

The exact source-tooling formats and round-trip behavior are defined in
`spec/source-tools.md`.

`star test` returns exit code 7 when any fixture fails. Fixture infrastructure
and file-access failures use the I/O exit code. The manifest supplies the
resource limits for each case; the CLI does not execute the test suite unless
the user invokes `star test`.

## Exit codes

| Code | Meaning |
|---:|---|
| 0 | Success |
| 2 | Usage or invalid option |
| 3 | Input/output or process-launch failure |
| 4 | Lexical, parse, semantic, lowering, compilation, or bytecode-verification diagnostic |
| 5 | Guest runtime failure |
| 6 | Configured resource limit exceeded |
| 7 | Online-judge fixture failure |

Diagnostics include the relevant file path and, for source-level errors, the
location reported by the lexer, parser, semantic analyzer, or lowering stage.
